# Demo D0: Foundations

What you can see:
- Repo https://github.com/satvik-jain-iitd/bhavna-ai with `main` (release), `dev` (integration).
- 46 issues: 12 epics (E0 to E11) and 33 stories, each story with its Gherkin, Definition of Ready checklist and Definition of Done. Labels: epic, story, v1 to v4, mac, windows, research, process, docs.
- `docs/` tree split from the plan: strategy, market, personas, experience, PRD, MVP, architecture, 11 ADRs, risks, backlog, process, research tables with tiers, experiments H1 to H8, test cases, journal, discussions, process trace, ideas.
- CI: GitHub Actions on macOS runs pytest on every push to dev or main and every PR. First run green (17 s).
- PR #1 (docs tree) merged to dev after CI.

How to run it: open the repo, read `docs/README.md`, run `uv run --python 3.12 --with pytest pytest -q tests`.

What was learned:
- Branch protection on a private repo needs GitHub Pro; "main only by PR" is a convention until the repo goes public or the plan is upgraded.
- The project board needs `gh auth refresh -s project,read:project` from the owner once.
- The backlog-to-issues script dropped the first story of each epic on the first pass; fixed with a second pass. Lesson for the playbook: verify the issue count against the backlog before moving on.
