# Demo D1: models ready, numbers on the table

What you can see:
- `models/` with every converted model (Apex MLX q8 837 MB, Apex CT2 int8 792 MB, tiny MLX + CT2,
  Parakeet v2 MLX bf16 1.2 GB, Parakeet ONNX, GGML files for the Windows gate).
- `tools/bench.py` output on 12 fixture clips (4 synthesised with macOS voices, 8 real human Hindi
  and Hinglish clips from the Apex repo), appended to `docs/research/experiments.md`.
- Gate decisions H1 to H4 and H8 filled in `experiments.md`.

How to run it (one model at a time, see RAM rules in `docs/process.md`):
```
ONLY=apex RUNS=3 uv run --python 3.12 --project macos --extra bench tools/bench.py
```

What was learned:
- The language router works on the first try: English 0.96 to 1.00, Hindi and Hinglish 0.00 to 0.43.
- Apex writes clean Roman Hinglish on real speech: "Kya iska svaad achchha hai?",
  "Mehnat to poora karte hain." English through Apex is word-perfect.
- Parakeet on Hindi is nonsense ("May not the poor can"), so a router or a single model is a must.
- Apex latency was the surprise: about 5 s per clip regardless of length, because whisper always
  encodes a 30 s window. Cutting the window to 10 s gave 2.0 s with the same text. This became
  ADR-012: a dynamic window in 5 s steps, and a lean profile with Apex alone (0.9 GB) as the Mac
  default, after the owner asked for RAM consideration.
- Benchmarks on a daily laptop need care: the first numbers were taken with 5.6 GB of swap in use.
  From now on one model per process, swap checked first, heavy runs only when the owner says.
